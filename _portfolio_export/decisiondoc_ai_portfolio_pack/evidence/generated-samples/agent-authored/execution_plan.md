# 수행계획서: [합성] 문서관리시스템 고도화 제안서

## 수행 총괄 요약
수행은 착수 후 6개월 동안 착수·분석, 설계, 구축, 시범·교육, 완료의 5단계로 진행합니다. 각 단계는 완료 기준과 산출물 승인을 거쳐 다음 단계로 넘어가며, 시범 부서 적용 결과를 확인한 뒤 전체 부서로 확대합니다. 관리자·사용자 교육 각 1회는 시범 단계에서 실시해 운영 전환 전에 사용 절차를 정착시킵니다.

## 추진 체계
| 역할 | 인원·등급 | 책임 | 투입 시점 |
| --- | --- | --- | --- |
| 사업관리자(PM) | 인원·등급 제안사 확정 | 일정·범위·발주기관 협의 총괄 | 착수부터 완료까지 |
| 연계·개발 담당 | 인원·등급 제안사 확정 | 전자결재 연계, 저장소, 검색 구축 | 설계부터 시범까지 |
| 보안 담당 | 인원·등급 제안사 확정 | 암호화와 접근 이력 설계·점검 | 설계부터 완료까지 |
| 교육·전환 담당 | 인원·등급 제안사 확정 | 교육 운영과 운영 전환 준비 | 시범부터 완료까지 |

## 추진 일정
| 마일스톤 | 시점 | 완료 기준 | 핵심 산출물 |
| --- | --- | --- | --- |
| 착수·분석 | 1개월차 | 현행 문서 흐름과 검색 소요 시간 기준선 측정 완료 | 착수보고서, 현황 분석서 |
| 설계 | 2개월차 | 연계·저장·검색·보안 설계 승인 | 설계서 |
| 구축 | 3~4개월차 | 연계 자동 보관과 검색 기능 구현 및 단위 시험 완료 | 시험 결과서 |
| 시범·교육 | 5개월차 | 시범 부서 적용과 교육 각 1회 완료 | 시범 운영 결과서, 교육 결과 |
| 완료 | 6개월차 | 전체 적용과 기준선 대비 효과 측정 완료 | 완료보고서, 운영 매뉴얼 |

## 수행 방법론
단계별 완료 기준을 먼저 합의하고 산출물 승인으로 다음 단계를 여는 단계형 방식을 사용합니다. 구축 단계에서는 결재 연계와 검색 기능을 작은 단위로 나누어 매 단위마다 시험 결과를 공유합니다.

## 거버넌스 및 보고 체계
발주기관 담당자와 사업관리자가 월 1회 진척 점검 회의를 열고, 단계 전환 시에는 산출물 승인 회의로 범위와 일정 변경 여부를 결정합니다. 범위 변경 요청은 변경 요청서로 기록한 뒤 영향 검토를 거쳐 승인합니다.

## 리스크 관리
| 리스크 | 영향 | 대응 방안 |
| --- | --- | --- |
| 전자결재 연계 사양 지연 | 구축 일정 지연 | 착수 단계에서 연계 사양 확인 일정을 확정하고 대체 수신 방식 준비 |
| 기존 문서 이관량 과다 | 시범 일정 지연 | 이관 대상과 순서를 착수 시 부서와 합의하고 단계적으로 이관 |
| AI 분류 정확도 미달 | 담당자 확인 부담 증가 | 정확도 기준 미달 유형은 수동 분류로 유지 |
